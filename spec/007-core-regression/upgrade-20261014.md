## Vision Buffer Ownership Upgrade

The old GC-safe pointer arithmetic alone is insufficient with Reality
`v0.0.0-20261014101318-83f621788ca8`: its `rawInput` is now a
`*bytes.Buffer`, not an inline `bytes.Buffer`. Reading the pointer slot as a
buffer corrupts adjacent connection fields. Reality can return an empty large
buffer to `rawInputPool` before reading another record, set the slot to nil,
and later replace it with a small or pooled buffer. Caching its dereference at
VLESS setup therefore also violates ownership.

`proxy.NewVisionBuffers` validates direct field types and the TLS read-lock
layout before unsafe access. It retains the connection with GC-visible
pointers. At the Vision direct switch, `Take` locks the TLS read mutex and
resolves the current pointer slot, copies pending plaintext followed by raw
bytes, clears the plaintext reader, and detaches the current Reality buffer.
It never returns a buffer to Reality's private pool or accesses an earlier
pooled buffer. Inline standard TLS/uTLS/encryption buffers retain the same
transfer ordering and are cleared after copying. Encryption retains its
existing exclusive-reader contract. Unsupported layouts and missing or repeated
transfers fail closed; raw-reader installation happens only after success.
Protocol framing, XOR/non-RAW splice guards, pin verification and dependency
pool behavior are unchanged. No dependency or shared build-file edits were
made by this worker.
