## Independent Trust Oracle

`TestSystemOnlyCATrustSelection` generates a private CA and DNS-name leaf. On
Linux it executes a fresh copy of its own test binary with SSL_CERT_FILE pointing
only to that root and SSL_CERT_DIR to an empty private directory. This isolates
the real OS-file-root loader and x509's once-cached roots from other tests.
Host/container system trust files are never edited. Child inherits the parent's
race-instrumented binary. GODEBUG disables forced fallback roots, not certificate
verification. There is no global root-pool replacement or mock trust factory.

Against a real loopback TLS HTTP server, production `Config.GetTLSConfig` must:

- Reject the system-only root with default bundled roots, specifically with
  `x509.UnknownAuthorityError`, not a timeout/connection failure.
- Accept it with `UseSystemCa=true`, with no configured custom certificate.
- Independently accept it as an explicit `AUTHORITY_VERIFY` certificate while
  system roots are disabled.
- Reject the wrong DNS name in both system and explicit-root modes, specifically
  with `x509.HostnameError`.
- Keep `InsecureSkipVerify=false` in every case. Successful requests have a
  verified chain and exact response payload.

Five subcases execute per child. Each child has a 30s parent deadline and each
HTTP request a 3s timeout; transports/server/process and private key files are
cleaned up. Non-Linux platforms explicitly skip this fixture because their
native trust stores do not follow this Linux environment contract. No macOS
Keychain changes or Darwin/Windows system-root execution are claimed.
