# Planned Verification: Core027 leastPing maxRTT

All cases are planned, not implemented or executed. Every boundary uses an independent expected tag/status,
not expected output generated by the same helper under test. Use synthetic identities and local endpoints;
never copy production addresses, users, keys or node snippets into this public repository.

The [spec's verification and acceptance section](spec.md#verification-and-acceptance) defines the required
fixtures, independent oracles, execution layers, pass/fail gates and evidence format. This file owns the
detailed case matrix; neither document is execution evidence.

| ID | Sequence | Required result |

| Y06 | A latched, rule publication replaces the balancer, A 45 | new balancer starts released; A chosen |
