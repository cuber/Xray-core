## Confirmed Migration Blockers

### R1: Removed ProxySettings Affects Sidecar, Not Just Node JSON

Selected upstream `infra/conf/xray.go:268` rejects outbound `proxySettings`, and
`app/proxyman/config.proto` reserves old field 3. Static scan finds one instance
in `hq`, but that is NOT the full blast radius:

- Sidecar `probe.go` builds it in `buildViaProbeXrayConfig` and
  `buildProbeOutboundWithTransports`, including SOCKS UDS transport indirection.
- Sidecar `proxychain.go:buildShadowsocksOutbound` also contains a legacy builder;
  current search finds no caller, so this is not counted as a proven live path.
- Core spec008 tests explicitly depend on proxySettings versus dialerProxy
  precedence, endpoint DNS location, chaining, cancellation and byte attribution.

Prefer migrating owned callers to streamSettings.sockopt.dialerProxy, but NOT a
blind field rename. Verify actual transport versus protocol chaining, Mux, UDP,
endpoint DNS, missing-hop fail-closed behavior and per-hop accounting. Decide
explicitly whether a temporary compatibility adapter is needed. Preserve the
behavioral oracles; do not merely delete the legacy tests to get a green build.

### R2: FinalRules Must Preserve Deliberate Local/Private Access

Current JSON scan: 45 configs, 46 ipsBlocked objects in 41 nodes, all `[]`.
Upstream `infra/conf/freedom.go:Build` only warns for that field. Freedom now uses
finalRules and protocol-dependent defaults; the default blocking delay is 30-90s.
Empty finalRules is NOT equivalent to old empty ipsBlocked. An explicit allow
rule is the candidate equivalent for intentionally unrestricted outbounds;
review each location before generating it.

Test loopback HTTP probes, private/WG targets, IPv4/IPv6, domain-to-private DNS,
public destinations, sidecar UDS and the dialerProxy bypass of finalRules.
Upstream default protocol dispatch does not mention AnyTLS; decide its parity
with our existing inbound behavior explicitly rather than inheriting accidental
different private-network policy.

### R3: SS-2022 Is an Engine Migration

Review includes native rewrite 65e853ed, follow-up 00863626 and selected-head
0888beb3. Do not replay common/singbridge changes onto deleted upstream files.
AnyTLS has no bridge import, but still needs its own Sing/UoT dependencies.

Source-confirmed improvements:

- Single/multi/relay TCP set a handshake deadline before authentication.
- `stream.go:InitServerStream` clears it after header decode; relay clears its
  deadline separately. Successful authenticated streams must survive beyond it.
- TCP transport now interrupts both link directions on failure; UDP sessions
  update the response connection when reusing a link.

Additional source-level concerns, NOT runtime-proven failures:

- Multi-user RemoveUser deletes identity maps but not cached UDP User/UserPSK.
  Existing UDP sessions can use cached credentials without another map lookup.
  Define and test removal/re-add semantics; do not silently accept stale access.
- Multi-user UDP allocates a session and replay window before user/payload
  authentication. `replay.go:GetOrCreate` has no capacity bound and triggers
  cleanup only on new session creation (at most once per 30s, expiry 500s here).
  Test unauthenticated churn and idle retention with bounded local fixtures.
- `EnsureLink` writes the user through the inherited inbound context pointer.
  Verify concurrent multi-user UDP isolation and race freedom, including reused
  transport connections; attribution must not switch to another user.
- Initial TCP fixed header is read with one Read and short reads are rejected.
  Exercise legitimate client framing over actual chained transports, not only
  localhost writes; preserve SIP022 constraints rather than casually changing it.

Required clients: independent sing-box/Mihomo/sslocal fixtures, old and new Core
in both client/server roles, multi-user keys, replay rejection, early/server-first
payload, TCP half-close, UDP roaming, RemoveUser and normal/user/domain counters.

### R4: Shared APIs and Protobuf Are Not Text-Merge Problems

- Stats Manager adds atomic GetOrRegister methods and removes free helper APIs.
  Retain optional DomainTrafficManager, update callers/mocks, and prove concurrent
  first registration never loses normal counters or double-counts domain traffic.
- SenderConfig.proxy_settings is removed; QuicParams field 5 changes type/meaning,
  field 13 changes meaning and max_incoming_streams moves to 15. Freedom field 8
  changes from IP rules to final rules. Old serialized messages are not presumed
  compatible. Regenerate protobuf from reviewed schemas; never resolve generated
  code by choosing ours/theirs. Test old/new Sidecar control clients and dynamic
  AddInbound/AddOutbound payloads, not only read-only status RPCs.
- Go requirement moves to 1.27; the prior successful fork validation used 1.26.1.
  Review module resolution with AnyTLS retained and rebuild all Core consumers.
- TLS now defaults to bundled roots, not OS-injected roots. Custom CA tests must
  provision explicit trust; do not restore insecure verification for convenience.
  Existing node JSON scan found none of the scanned removed TLS fields, but
  generated configs and tests require independent inspection.

Upstream OB `healthping.go` clamps intervals below 10s. That is incompatible with
our configured 3s contract. Upstream cancellation/initial result fixes do not
replace our full recovery and HTTP lifecycle implementation.

Hy2 post-tag changes are relevant: 7c2e05dc propagates dial cancellation and uses
a cancellable lock; 2bea2df6 snapshots the manager before cleaning clients;
c7dbfd5e removes clients owned by stopped Core instances. Our lock-outside-cleanup
intent partially overlaps, but structural equivalence and instance churn still
need tests. Do not restore the old dialer wholesale while resolving conflicts.

Router now uses atomic rules/balancer pointers. Port detailed configuration clones
and weighted selection onto it. `ReloadRules` has error exits after preparing
webhooks without explicit cleanup of that newly built set; validate rollback and
resource ownership with failure injection. Separate atomic stores are not by
themselves proof that every multi-object API sees one coherent generation.

## Memory Review

New matcher code uses compact arena/offset storage, streaming DAT loading, regex
prefilters and weak shared caches. This is relevant to retained routing memory,
but no memory reduction has been measured here. Gate with an independent matcher
oracle (full/domain/subdomain/regex/case/attrs), fixed production-like DAT hashes,
repeated route replacement and GC. Measure build peak, retained heap, RSS and
lookup cost separately. Keep THP experiments independent from the code upgrade.

## Recommended Integration and Test Order

1. Promote only after implementation approval; keep this review in draft meanwhile.
   Preserve current develop/backup. Start a temporary candidate at the full target
   SHA; do not switch production build pins during conflict resolution.
2. Establish upstream toolchain/build/test baseline, recording its own failures.
   Validate native SS and the risks above before transporting traffic features.
3. Port shared 002/007 prerequisites and required 003 dialer/listener behavior.
   Treat shared portions of 004 as prerequisites to 008, not numeric-sort replay.
4. Port 004/005/006/009, retaining reviewed upstream improvements. Test each stage
   with its existing spec oracles and an explicit diff against upstream.
5. Port 008; migrate Sidecar via/UDS builders and configuration policy separately.
   Use isolated consumer module files/worktrees until the candidate is accepted.
6. Run full uncached race tests, vet/format, external-client/chain matrix and
   Darwin/Linux release builds under the existing clean-commit build rules.
   No report of all-green may hide opt-in integrations that were skipped.
7. Validate all 45 current JSON configs plus dynamic generated configurations with
   required cert assets, then compare routing results and control-plane payloads.
8. Authorize/adopt the tested candidate and pins separately, then deploy by SOP
   with previous binaries/configs retained. Observe sockets/live heap/FDs under
   traffic and churn for 24-48h; no automatic production upgrade in this task.

Rebase remains a possible Git mechanism, not the acceptance strategy. A blind
18-commit rebase can restore code removed for good reasons and erase upstream
fixes while resolving conflicts. Prefer contract-led replay/porting onto the
fixed upstream base, using cherry-pick where genuinely independent.
