# Candidate Lifecycle Verification

Candidate: `rebase/main-20261014`, upstream `0888beb3`, dirty integration tree.
Recorded 2026-10-14; no production deployment or canonical pin change.

## Adaptation

- Preserve upstream QUIC's concrete `*cnc.Connection` requirement. Dispatch
  cancellation is attached via its close hook rather than another connection
  wrapper that breaks downstream type assertions.
- Hy2 keeps upstream per-client admission channels and per-request contexts.
  Manager cleanup snapshots clients without holding the registry lock over I/O,
  and removes only the same still-current entry. Retired Core instances cannot
  be reused to dial. Unsupported dialer connection types close rather than panic.
- Shared readv retains upstream platform behavior, including Windows' initial
  readiness poll, while propagating terminal errors. This is covered separately
  from QUIC/Hy2 ownership.

## Executed Tests

`TestUpgradeHy2FailedAuthenticationReleasesSockets` uses a real local HTTP/3
server. Each run attempts 100 forbidden authentications, 100 untrusted TLS
handshakes and 100 deadline cancellations during authentication. It checks
actual UDP socket closure after **each** attempt, nil transport/session fields,
and exact HTTP handler counts (untrusted TLS must never reach the handler).
No remote endpoint, certificate-verification bypass or mock successful dial is
used. Additional tests cover admission cancellation, global-registry progress
while a client lock is held, retired instances and unsupported connection cleanup.

## UDP Shutdown Race Found by Integration

The first broad race run failed AnyTLS-over-Hy2 chain/fault/process tests with a
real shared transport race: `udpSessionManager.clean` read `closed` outside its
RWMutex while `run` wrote it under the lock. This is independent of the successful
failed-authentication socket tests above. Cleanup now reads manager state under
the same lock. `InterConn.closed`, read by datagram writes concurrently with
manager closure, is atomic; idle cleanup rechecks activity before closing a
previously sampled session.

`TestUpgradeHy2UDPConcurrentWriteAndClose` races four writers/cleaners with
manager retirement over 100 rounds, then checks empty registry, rejected writes
and EOF. `go test -race ./transport/internet/hysteria -run
TestUpgradeHy2UDPConcurrentWriteAndClose -count=10 -timeout=2m` passes (1.655s).
The failing end-to-end Hy2 chain/process cases must also be rerun before this
integration regression is closed.

## Remaining Acceptance

### UDP worker retirement follow-up (2026-10-15)

Sidecar's full-instance SS2-over-Hy2 churn exposed retained `processUDP` readers
after the protocol/session tests passed. The UDP worker closed its socket and
proxy but not the active per-source pipes. Worker Close now rejects new admission,
detaches the connection map under its lock, and cancels/closes each connection
outside that lock. Context cancellation is installed before publication, not
assigned later in the handler goroutine. Expiry uses the same ownership rule;
an old handler may remove only its own map entry, never a replacement connection.
Pipe reader interruption also releases queued payloads. A late checker Start is
closed again if worker shutdown raced with it; errors do not panic the server.

`TestUDPWorkerCloseReleasesActivePipes`,
`TestUDPWorkerRetiredHandlerCannotRemoveReplacement`, and
`TestUDPWorkerConcurrentAdmissionAndClose` pass 20 race repetitions in 1.854s.
The actual Sidecar regressions `TestCandidateSS2UDPReaderRetires` and
`TestProbeChainCandidateResourceChurn` pass three race repetitions in 20.067s,
including the previously failing three-reader reproduction. Logs are
`/tmp/core-upgrade-udp-worker-retirement.log` and
`/tmp/sidecar-upgrade-udp-retirement-fixed.log`.

These tests are separate from the one-hour protocol-level SS soak: that earlier
soak did not exercise Core inbound worker teardown and must not be used as proof
of this subsequently repaired boundary.

### Broader acceptance

These scoped results do not prove a complete upgrade or prolonged leak freedom.
Native SS2022 resource tests, external-client interoperability, full uncached
regressions, Sidecar integration, configuration migration and the long-duration
memory/FD workloads remain owned by spec010's acceptance ledger.
